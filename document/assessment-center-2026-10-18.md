# 门户评估中心：角色工作流

用户纠正了上一版预约意图。本次将 `/assessment` 改为正式评估中心，移除预约表单、菜单和读写接口。旧预约表仅保留已有数据，不再供门户操作。

界面沿用门户现有绿色语义色、字体、间距及 Arco 组件；使用明确的标签、进度数字和空/错/加载/禁用反馈，不引入新的视觉体系。

## 页面与流程

| 身份 | 功能 |
| --- | --- |
| 访客 | PEAK 预评估方法、D/G 模块及“安排评估 → 逐项记录 → 报告与练习”的说明；登录入口 |
| 老师、管理员 | 为正常学生安排 D 或 G 模块，查看评估进度，按原有授权材料逐项施测、保存反应与备注，完成复核后记录锁定 |
| 学生 | 查看本人评估进度、完成报告、逐项实际反应，进入老师确认的针对性练习 |
| 家长 | 仅查看管理员已关联孩子的评估与报告，进入孩子的针对性练习；陪练计入孩子记录，另存实际操作账号 |
| 管理员 | 在成员管理中设置或撤销家长与学生的关联 |
| 培训师 | 保持培训职责，不开放学生评估和结果 |

报告展示已记录、正确反应、未通过、未评估、领域概览与逐项记录。未评估不默认为 0；报告不提供标准分和诊断解释。当前正式接入方法为既有 PEAK 预评估，D/G 各 64 项，复用原有固定版本、校验及只读锁定规则。VB-MAPP 等旧记录不被改名、迁移或混入 PEAK。

针对性练习由老师明确选择本次评估的已记录项目，关联有练习题的题库教学目标，并填写具体练习目标。没有自动把所有低分项目映射到某个学科，也不直接用正式评估材料作为练习题。

## 数据与权限

新增 `parent_student_links` 表，由管理员管理关系；`portal_attempts` 增补 `actor_id` 保存实际操作账号。原 `peak_assessments`、`peak_scores`、`student_learning_plans` 继续使用，不复制历史记录。老师确认的练习目标写入既有教学计划表。

所有评估接口在服务端校验角色，学生强制本人范围，家长按已关联学生校验；修改学生筛选参数不会扩大范围。家长和学生不获得教师指令、材料定义或施测备注，也不能安排、评分、完成评估或确认目标。撤销关联后，报告和练习接口立即拒绝。家长练习必须指定有效的确认目标，题目必须属于对应教学目标；不能更改 URL 获取其他学生、其他目标或其他题目。
