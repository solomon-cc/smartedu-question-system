# 评估与题库产品改进建议

基于当前仓库代码、既有 PEAK 施测材料、2026-10-09 官方产品文档。公开产品能力不是付费后台体验或教学效果证明；这份评审快照形成时尚未新增业务代码，也未完成浏览器视觉实测；随后本轮实现了学生教学跟进主线，见 [实施说明](student-learning-workflow.md)。

## 参考对象

- [Emergent PEAK/AIM Digital](https://www.emergent-digital.com/peak-aim)：专用内容、数据采集、学生 / 教职员工 / 管理角色、目标库及家庭材料。参考材料与记录的组织方式，不补造用户未提供的量表内容。
- [CentralReach CR LiftEd](https://edu.centralreach.com/products/lifted/)：评估发现与教学目标对齐、技能及任务分析记录、进度图和报告。其 FAQ 明确称 CR Assessments 与 LiftEd 没有直接产品集成，不能据此宣称全自动对接。
- [Moodle 题库](https://docs.moodle.org/en/Question_bank)：分类、草稿 / 可用、版本、作者、同事评论、使用情况与质量检查。参考题库管理，不照搬普通考试流程到老师主导的评估。
- [TAO 工作流](https://userguide.taotesting.com/knowledge-base/latest/public/tao-full-workflow-overview)：题目编制、组卷、施测、人工评分 / 复核与报告的职责分离。

## 已具备的基础

- Assessment.vue / PeakSession.vue：D、G 各 64 项，有授权图片材料、教师指令、人工评分、实际反应 / 备注、断点继续及完成锁定。
- Questions.vue / Question：图文题、学科、年级、题型、提示、教学目标关联；题目模型已有作答次数和正确率。
- Teaching.vue / integrity.go：试卷、作业、指定学生；已保存试卷题目快照及所选顺序，避免旧任务随题库变更而漂移。
- Ability.vue：教学主题、目标和从练习产生的能力记录。
- 三角色已有共同导航与视觉规范，教师课堂预览不会生成学生学习记录。

## 第一阶段：先连接业务与解释数据

### 1. 学生档案成为老师的主要工作入口

现有学生详情主要汇集作业与答题数据。增加同一学生的评估、教学目标、待办、练习和阶段报告入口，携带 studentId 跳转，减少每个模块重新选人的操作。

验收：从学生档案开始一次 PEAK 评估，返回后仍停留在该学生上下文；能看到同一学生的未完成评估和下次待办。

### 2. 评估项目关联目标，再生成教学计划草稿

当前 Question.objectiveId 已存在，但 PEAK 项目与 SkillObjective 之间没有显式关联。先建立经教师确认的项目 / 能力到目标映射，再让教师从评估记录勾选“需继续观察 / 待巩固”项目，形成目标草稿、匹配教学题目、安排练习。

不根据单次原始分自动诊断、自动定级或直接发布教学计划；正式评估材料和日常训练变式分别管理，不默认把评估原题当作反复训练题。

验收：评估来源、目标、对应题目、作业和后续观察互相可追溯；目标经过教师确认才发布。

### 3. 区分本次表现与稳定掌握

handlers.go 当前以一次提交中目标正确率 >= 80 生成 Status=Y；Ability.vue 将其展示为“已达标”。缺少样本数量、帮助程度与连续观察维度。先把统计状态解释为“本次达到阈值”，再增加每目标可配置的掌握标准。

新增记录维度用于教学观察，不能擅自改变 PEAK 原评分规则：独立 / 接受提示、首次 / 多次尝试、教师备注、观察场景。将持续达标、保持和泛化作为教师可核对的证据，具体标准由老师按目标设定，不设置通用的专业判定。

验收：仅做 1 道题答对不会直接显示“稳定掌握”；教师能看到判定依据和原始记录。

## 第二阶段：提高老师施测、备课和报告效率

### 4. 多方法评估框架

保留“评估中心 / 我的评估”通用入口；各工具保留独立版本、模块、项目、评分方式及说明。统一管理施测准备、记录、复核和完成，方法特有规则放在各自实现中。先抽取 PEAK 共用流程，再接第二种评估，避免空泛设计。

验收：同一学生可查看多方法记录；PEAK 二元记录与其他工具计分不混算。

### 5. 老师与学生的独立展示

共用屏幕模式继续保留“只看题目”；后续增加独立题目展示页，可由老师电脑控制、平板呈现给孩子。施测前提供材料准备清单、G 作答册、投屏 / 图片预览和操作演练。

验收：学生展示页不含答案、教师指令或评分；步骤同步；连接失败时保留当前记录并明确状态。

### 6. 题库从编辑列表走向内容管理

在已有学科、年级和目标关联之上，增加能力维度、反应方式、难度 / 支持程度、生活场景标签；支持按目标找题及建立教学变式。再增加草稿、审核、发布、停用、修订版本及来源。

沿用现有题目快照；新版本不覆盖已发布任务与历史记录。利用已有作答次数 / 正确率做题目回顾，并注明样本数量与统计口径，不在小样本上自动宣布题目质量好坏。

验收：草稿不能进入正式作业；老师能看到修订差异；按目标选题后能进行学生视角预览。

### 7. 面向沟通的结果页

增加同工具、同版本、同模块的两次记录对比，用项目网格展示新增通过、仍待观察及未评项；分母、有效记录数量和日期明确显示。教师报告保留实际反应与观察依据；学生看到完成与成长信息。家庭报告先提供教师审核的简明 PDF，不急于新增家长角色。

验收：未评不计为失败；原始反应统计不标成标准分；不能跨方法直接比较总分。

## 第三阶段：团队规模扩大后再补

- 管理员内容工作台：待审核题目、版本变更、素材缺失、数据同步异常、复测待办。
- 教师协作：负责学生、评估执行 / 复核、教学目标维护等职责明确。
- 统一故障反馈与操作审计；需要时加入弱网队列、冲突处理和导入标准。
- AI 如引入，仅用于检索、标签建议、题目草稿或报告措辞；专业评分和正式目标仍由教师确认。

## 推荐验收顺序

1. 学生档案连通 PEAK、目标和作业。
2. 将一次正确率与持续掌握分开解释。
3. 做教师确认的评估到教学目标流程。
4. 增强目标选题、内容审核和版本管理。
5. 同版本复测对比、教师审核报告、双设备施测。

界面改动沿用现有设计系统并参考 ui-ux-pro-max：围绕角色主要任务安排入口、减少重复选人、显示清晰的准备 / 保存 / 复核状态、兼顾键盘与平板操作。以上是建议，尚未实施。
